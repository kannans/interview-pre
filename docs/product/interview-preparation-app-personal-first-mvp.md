# Interview Preparation Coach Personal-First MVP

## Document Purpose

This document defines the first and most important version of the product:

`build the app first to solve my own interview recovery problem`

This is not the broad startup version.

This is the personal-first version focused on one user:

- an experienced engineer
- strong in real work
- weak in interview-style coding and answering
- trying to prepare better, track progress, and get selected

## Core Principle

The first success of this product is not revenue.

The first success is:

- helping me prepare consistently
- helping me improve coding basics
- helping me answer better
- helping me track progress
- helping me perform better in real interviews

If it works for me, then it can help others.

## The Real Problem to Solve

This app exists because of a real pain:

- I have 15 years of experience
- I am not able to answer properly in interviews
- I struggle with basic coding and problem solving under pressure
- I need a better way to prepare
- I need to know whether I am improving

So the product should not begin as a marketplace, job portal, or broad interview platform.

It should begin as a focused interview recovery system.

## Personal-First Product Goal

Help one experienced engineer move from:

- interview rust
- weak coding confidence
- random preparation
- inconsistent practice

to:

- structured preparation
- improved coding basics
- better technical answering
- visible progress
- stronger interview readiness

## First User Definition

### Primary User

- 15 years experienced engineer
- preparing for job change
- wants better package and better company
- fails in coding rounds or basic programming rounds
- needs guided recovery, not generic content

### User Mindset

- not looking for entertainment
- not looking for random DSA lists
- wants practical preparation
- wants confidence recovery
- wants real improvement before next interview

## What This MVP Must Do

The MVP should help answer these questions:

- what should I prepare today
- where am I weak right now
- am I improving or not
- can I solve basic coding questions better than before
- am I answering interview questions more clearly
- what should I practice next

## MVP Scope

### 1. Preparation Profile

The app should allow the user to define:

- years of experience
- current role
- target role
- target companies
- primary weak areas
- interview timeline

Why this matters:

- the plan should feel personal, not generic

### 2. Interview Weakness Diagnosis

The app should identify the main recovery areas using a baseline assessment, not only self-selection.

The baseline assessment should include:

- a short basic programming test
- a starter DSA question set
- one technical explanation prompt
- one behavioral or project-explanation prompt
- a self-rating for confidence and interview anxiety

The app should identify recovery areas such as:

- basic programming
- DSA fundamentals
- React / frontend interview weakness
- answer structuring
- confidence and communication

Why this matters:

- before practice, the app should diagnose what is actually broken
- the first plan should be based on evidence, not only feeling

### 3. Personalized Recovery Plan

The app should generate a simple plan such as:

- what to revise
- what to practice today
- what to complete this week
- what to defer for later

Why this matters:

- reduces random preparation
- creates a repeatable preparation system

### 4. Basic Programming Recovery

The app should support basic coding recovery in measurable levels.

Level 1: programming basics

- loops
- conditions
- functions

Level 2: core data handling

- strings
- arrays
- objects or maps

Level 3: logic-building under pressure

- logic-building exercises
- simple timed problems
- repeated mistake review

Level 4: interview-style basics

- write clean code without hints
- explain the approach before coding
- handle edge cases

Why this matters:

- the user should stop failing simple coding rounds
- progress should be visible by level, not only by topic

### 5. DSA Recovery Track

The app should provide structured topic practice in levels.

Level 1: high-frequency foundations

- arrays
- strings
- hash maps

Level 2: common coding patterns

- two pointers
- sliding window
- recursion basics

Level 3: intermediate structures

- linked lists
- stacks and queues
- trees

Level 4: interview readiness

- mixed topic problems
- timed practice
- repeated weak-pattern review

Why this matters:

- focus on the most common interview patterns first
- avoid jumping into hard DSA before rebuilding confidence

### 6. Mock Question Practice

The app should ask realistic interview questions and coding problems:

- one by one
- with follow-up prompts
- with answer feedback

Feedback should be scored using a simple rubric:

- correctness
- problem-solving approach
- edge cases
- code clarity
- communication clarity
- confidence
- time taken

Why this matters:

- preparation should feel interview-like, not passive
- feedback should explain why an answer was weak and how to improve it

### 7. Progress Tracking

The app should show:

- completed sessions
- weak topics
- improved topics
- coding success rate
- answer quality trend
- confidence trend if possible

Why this matters:

- progress must be visible to keep motivation strong

### 8. Daily or Weekly Practice Log

The app should record:

- what I practiced
- what I solved
- where I struggled
- what to do next

Why this matters:

- practice should not disappear after each session

## What This MVP Does Not Need Yet

The first version does not need:

- job portal features
- vacancy aggregation
- full CV / JD role-fit analysis
- advanced resume marketplace
- voice interview system
- large company database
- public community features
- heavy gamification
- multi-role complexity

CV / JD analysis can come later after the personal interview recovery loop is working. In the first version, the focus should stay on preparation, practice, and progress.

## Suggested MVP User Flow

1. User creates profile
2. User completes the baseline diagnosis
3. App identifies weak areas
4. App generates recovery plan
5. User starts basic programming and DSA recovery
6. User practices one mock question or coding task daily
7. App scores progress and updates weak areas
8. User sees whether readiness is improving week by week

## Success Criteria for Personal-First MVP

This MVP is successful if it helps the user:

- practice at least 20 days in a 30-day period
- complete at least 30 basic programming problems
- complete at least 20 DSA recovery problems
- complete at least 4 mock interview sessions
- improve coding correctness from baseline by at least 25%
- reduce repeated mistakes in the same topic over time
- improve answer-structure score across mock sessions
- track preparation progress every week
- feel more ready before interviews based on a weekly self-rating

The first measurable target is not perfection. The first target is visible improvement.

## Best MVP Outcome

The best early outcome is not:

- many users
- big revenue
- broad feature set

The best early outcome is:

`This app genuinely helps me prepare better and perform better in interviews.`

## Personal Validation Questions

After using the MVP for a few weeks, the user should be able to answer:

- did I practice at least 20 days this month
- did I solve more basic problems without hints
- did my repeated mistakes reduce
- did my mock interview score improve
- do I know my weak areas more clearly
- am I answering with better structure
- do I feel more confident for my next interview

If most of these answers become yes, then the MVP is working.

### Week 1 Minimum Usable Release

- profile setup
- baseline weakness diagnosis
- daily practice log
- basic progress dashboard
- manual entry for practice results

### Phase 1

- profile setup
- weakness diagnosis
- personalized recovery plan

### Phase 2

- basic programming recovery
- DSA recovery track

### Phase 3

- mock question practice
- answer feedback
- session tracking

### Phase 4

- weekly progress dashboard
- readiness trend
- plan updates

## Why This Approach Is Strong

This approach is strong because:

- it solves a real personal pain first
- it avoids broad startup distraction
- it creates practical product clarity
- it gives real usage feedback
- it increases the chance of building something useful

## Founder Reminder

Do not ask first:

- how big can this become
- how many features should we add
- how do we beat every competitor

Ask first:

- did this help me prepare today
- did this reduce my confusion
- did this improve my coding confidence
- did this make me feel more ready

That is the right first milestone.

## Final Summary

The personal-first MVP should be a focused interview recovery tool for one experienced engineer who wants to prepare better, track progress, improve coding basics, answer more clearly, and become interview-ready.

If it solves that problem well, it becomes a real product foundation.
